# 舱单数据定义

id是主单、分组单或箱货明细唯一字符串编号，parent为空表示主单。节点申报件数、净重和毛重是其完整子树的申报总量，校验时只加直接子节点，避免多层重复计数。包装carton=1件，pallet=10件；重量kg与t统一为kg。件数必须非负整数，净重非负且毛重不得低于净重。
拆并结构采用每节点最多一个父级的有向图；自环、长环、缺父级均阻断封存，保留环路径。不会以平面求和替代逐层校验。
危险品按明确分类与UN编号检查，3类与5.1类禁止同箱；未知分类和缺失编号需复核。此演示规则只覆盖文中三类，不替代运输合规审批。
报关总量只汇总主单，与context.json内的申报件数、净重和毛重逐项比较。重复同值折叠，重复编号冲突全部隔离。原始计数=采纳+隔离+空行+重复表头+重复同值行。
封存需所有图、重量、危险品和采信问题处理完毕。数值均Decimal，对外字符串保留精度，编号不转整数。

## 箱门重量交接

三类证据分开保存，不得互相覆盖：`weighing` 记录码头整箱毛重与称重时读到的封签，`tare` 记录空箱皮重，`seal` 记录申报原始封签。箱内货毛重=整箱毛重-皮重；称重封签与申报封签不一致时两者并列，申报封签始终以 `seal` 台账为准。

口径 `basis` 只有两种：`weighing`（可复核称重口径）与 `declared`（原申报保全）。默认只在称重齐全、封签一致、无结构阻断且差异在容差内时采用 `weighing`；否则保留 `declared` 并把差异挂为阻断。明确切换为 `weighing` 时若存在差异，必须同时给出差异说明，否则拒绝。

守恒核对分两层：`counted_once` 表示每个可达叶节点恰好落进一个箱、祖先不重复加总；`reconciled` 表示拆并前后件净毛完全相等。无主单节点不计入箱合计，但单独列出并阻断封存。

instruction 只改变批次内版本，不改变批号。同一 instruction（按排序后的 JSON 摘要）重试不新增版本；`restore` 只移动当前指针，历史版本与快照中的原始封签均保留。
